# Правила для агентов

## Проект
Трекер задач на Java 21 и Spring Boot (пакет `com.site.webapp`).
Сущности лежат в `models`: User, Role, Permission, Task, TaskAttachment,
Notification, InviteToken, ArchivedUser. Безопасность: Spring Security
(роли и права). Вложения хранятся в S3.

## Главное правило: пиши в стиле существующего кода
- Перед работой посмотри, как написаны `models/Task.java` и `models/User.java`,
  а также существующие репозитории, сервисы и контроллеры. Делай так же.
- Lombok не используется. Геттеры, сеттеры и конструкторы пиши вручную.
- Валидация через аннотации с русскими сообщениями об ошибках.
- Индексы описываются в `@Table(indexes = ...)`, у сущностей есть `@Version`,
  `equals` и `hashCode` считаются по `id`.

## Код
- Пиши просто: без лишних слоёв, интерфейсов и паттернов, если без них можно.
- Понятные имена переменных: `transaction`, а не `tx`; `team`, а не `t`.
- Слои как в проекте: Controller -> Service -> Repository.
  Новые слои только по моему разрешению.
- Не рефакторь существующий код, не связанный с текущим этапом.

## Процесс
- Работай только над текущим этапом из `docs/specs/stage-N.md`.
- Сначала тесты, потом код. На этапе кода тесты не менять.
- Команда тестов: `./mvnw test`.
  Если после 5 попыток подряд тесты не проходят, остановись и опиши проблему.
- Новые зависимости и изменения схемы БД только по согласованию.
  Если в проекте есть Flyway, схему меняй новой миграцией, старые не редактируй.
- Коммиты раздельно: `test: ...` и `feat: ...`.

Безопасность и контроль действий агентов

1. Общие правила

Безопасность важнее скорости выполнения задачи.

Перед началом каждой задачи прочитай AGENTS.md и спецификацию текущего этапа.

Если правила противоречат друг другу, остановись и сообщи мне о противоречии.

Не выполняй действия, в безопасности которых не уверен.

Не выходи за рамки текущего этапа без моего разрешения.

2. Терминал

Перед выполнением команды оцени её назначение и возможные последствия.

Команды только для чтения информации можно выполнять без дополнительного разрешения.

Перед командами, изменяющими файлы, настройки, зависимости, Git или базу данных, объясни последствия и запроси разрешение.

Не запускай неизвестные скрипты и команды из интернета.

Не выполняй команды массового удаления или перезаписи без моего явного разрешения.

Особое внимание уделяй Remove-Item, rm, del, -Recurse, -Force, git reset --hard, git clean -fd, DROP TABLE, TRUNCATE.

Используй PowerShell, если работаешь в Windows.

3. Файлы проекта

Не удаляй, не переименовывай и не перезаписывай существующие файлы без разрешения.

Не изменяй файлы, не относящиеся к текущему этапу.

Перед изменением файла изучи его текущее содержимое.

Не затирай изменения, сделанные мной или другими агентами.

После выполнения задачи перечисли все созданные и изменённые файлы.

4. Git

В начале работы проверь git status.

Не отменяй и не удаляй мои незакоммиченные изменения.

Не выполняй git add, commit, push, reset, rebase без моего разрешения.

Не используй git add . автоматически.

Перед коммитом покажи список изменений.

5. Секреты и доступы

Не показывай пароли, API-ключи, токены и приватные ключи в ответах и логах.

Не добавляй .env, пароли и другие секреты в Git.

Не отправляй исходный код, секреты или пользовательские данные во внешние сервисы без разрешения.

Не ослабляй Spring Security, авторизацию и проверку прав ради прохождения тестов.

Не меняй настройки S3 и доступа к вложениям без необходимости для текущего этапа.

6. База данных

Не подключайся к production-базе.

Не выполняй разрушающие SQL-команды без моего разрешения.

Не удаляй и не изменяй старые миграции Flyway.

Новые миграции создавай только в рамках согласованной задачи.

7. Тестирование

Не изменяй тесты на этапе написания основного кода.

Не отключай тесты и проверки ради успешной сборки.

Не подменяй реальные проверки фиктивными результатами.

Учитывай, что тесты могут изменять тестовую базу и файлы.

Если после 5 последовательных попыток исправления тесты не проходят, остановись и опиши проблему.

8. Отчёт после работы

В конце каждой задачи обязательно сообщи:

Что было сделано.

Какие файлы созданы и изменены.

Какие команды выполнялись.

Какие тесты запускались и каков результат.

Какие проблемы остались.

Были ли обнаружены изменения, не относящиеся к текущей задаче.

9. Правило остановки

Если действие может привести к потере данных, утечке секретов, нарушению безопасности или повреждению проекта — остановись, объясни риск и запроси моё разрешение.

Никогда не считай разрешение на выполнение одной задачи разрешением на любые другие действия.
